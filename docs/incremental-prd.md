# 华为 PC 营销软文智能体：前后端增量接入 PRD

## 1. 项目信息与边界

- Language：中文。
- Programming Language：沿用 HTML/CSS/原生 JavaScript + Python；保留五页 Hash SPA、经典 script 标签和现有视觉，不引入 Vite/React 重写。
- Project Name：`huawei_pc_agent_integration`。
- 原始需求：将 `frontend/` 每个现有功能接到 Python 七层业务能力，完成连接、任务、策略、取证成稿、核验、修订和导出闭环。
- 本文依据：`frontend/README.md`、`index.html`、`js/app.js`、`js/mock-data.js`、`agent/` 业务模块、`ARCHITECTURE.md` 及 `handoff-extracted/handoff/完整前端与产品方案.md`。这是代码静态审阅后的目标需求，不表示功能或外部 API 已实测。
- 本轮范围：补充薄 HTTP 适配与必要业务断点；复用 Python 层，服务端掌握事实、策略、稿件及核验结果。仅本机使用；多人账户、云部署与额外四个平台不进入本轮 P0。

## 2. 产品定义

### Product Goals

1. 闭环可用：现有五页全部主要操作调用 Python 能力；四个渠道均能完成至少一条生成、修订、复制/导出路径。
2. 结果可信：每个已使用产品事实、图片均有可核对来源和型号；无证据参数、价格及补贴不得成为正文或 CTA 的已确认承诺。
3. 状态一致：页面、四段输出、核验签章与导出均指向同一版稿件；失败、降级、未核验三种情况不显示为成功。

### User Stories

- 作为门店营销人员，我希望确认账号和指定库的真实可用状态，以免把演示内容当成知识库结果。
- 作为内容运营，我希望填写产品、人群、场景和渠道后看到可解释策略，以便在生成前判断适配性。
- 作为审核人员，我希望查看事实、图片来源和具体拦截原因，以便判断稿件能否使用。
- 作为编辑，我希望删段、换渠道、调整卖点、改 CTA 后重新核验，以便保留可信依据并快速改稿。
- 作为交付人员，我希望复制或导出的内容与当前预览一致并带核验摘要，以便线下交接。

## 4. 五页流程与 UI 增量

保留连接双卡、任务表单、策略卡、成稿三栏+四个 Tab、修订双栏。增量只增加状态、错误、数据来源、图片预览及必要字段提示。

| 页面 | 主流程与接口责任 | 解锁/失效条件 |
|---|---|---|
| `#connect` | 初次加载/重新探测 → 服务端检查环境与指定库 → 展示掩码、真实库名/ID、探测时间及每项结果 → 确认进入任务 | 初始为“检测中”；`failed` 阻断；本地模式明确为“本地镜像”，按允许的演示模式进入；不能默认绿灯 |
| `#task` | 读表单即时预览 → 本地必填提示 → 提交服务端归一化校验 → 缺项保留原值并追问 → 完整后产生 TaskSpec 和 ContentPlan | 产品/人群/场景/渠道/目标缺失时禁止出策略；已填购买阶段/问题完整透传；任务变更后旧策略与稿件标过期，不能作为新任务结果使用 |
| `#strategy` | 显示服务端切角、卖点顺序、结构、语气、字数区间、图片区间、CTA 及规则依据 → 按此策略生成 | 只允许按当前策略版本生成；返回任务不丢输入；未知场景提示选择，不静默套用开学季 |
| `#draft` | 请求检索/事实/生成/核验 → 显示已知执行状态 → 三栏呈现同一结果包 → 四个 Tab 可追溯同稿 | 请求完成且业务结果包齐全才显示“核验完成”；`FAIL` 可查看诊断但不解锁修订；返回策略或任务重试 |
| `#revise` | 读当前已核验版本 → 提交结构化修改 → 需要时先重建策略，再重跑 5→6 → 原子更新预览、报告、对比 → 复制/MD/TXT | 请求中禁用重复提交及当前稿导出；修订业务核验失败则展示失败稿并禁用导出；可明确返回上个通过版本；请求异常保留原稿及修改输入 |

修订语义必须与控件一致：“删除最后一段正文”删除当前稿件最后一个可编辑内容段，保留免责尾句；不能仅缩短字数预算代替删段。若无可删内容段，给出无操作原因。“屏幕/续航优先”实际改变内容顺序或侧重；“改 CTA”精确保存提交值并重新核验。换渠道同时更新 TaskSpec、ContentPlan、字数与配图约束，不沿用旧渠道策略。

## 6. 前后端 API 契约需求

以下路径是建议契约，仓库当前没有 HTTP API；架构实现可调整命名，但必须保持语义和字段一致。推荐同源提供静态文件，双击 `file://` 保留为静态查看入口并提示 API 启动方式。

| 建议接口 | 输入 | 输出/调用 Python 层 |
|---|---|---|
| `GET /api/status` | 无 | 账号掩码、库名/ID、`connection`、`checked_at`、`probes[]`、降级说明、允许模式；`check_knowledge_base()` |
| `POST /api/connection/probe` | 指定库配置引用，不收明文密钥 | 刷新后的状态；每项 `name/status/duration_ms/detail`，未执行为 skipped |
| `GET /api/options` | 无 | 产品候选、8 场景 ID/中文标签、4 渠道 ID/中文标签；来源于本地索引和策略配置 |
| `POST /api/plan` | `{task: TaskInput}` | `{task_id, task, plan, version}`；缺项返回结构化 `missing_info`，无可用策略 |
| `POST /api/generate` | `{task_id, version}` 或服务端校验后的完整 task/plan | `ResultBundle`；调用检索→事实→生成→核验；不能接受前端传入的 PASS 作为核验结论 |
| `POST /api/revise` | `{result_id, version, changes:{delete_last_section,platform,highlight,cta}}` | 新 `ResultBundle`、`previous_result_id`、`changed[]`；服务端重建策略并重跑 5→6 |
| `GET /api/results/{id}/export?format=md|txt` | 结果版本标识与格式 | 下载内容或 `{filename,mime,content}`；调用服务端格式化；复制使用同版 TXT 内容 |
| `GET /api/assets/{asset_id}` | 结果关联的资源 ID | 受控图片二进制；本地绝对路径不直接作为浏览器 `src`，不提供任意文件读取 |

统一结果包建议字段：`result_id, version, task, plan, evidence, article, report, segments, retrieval_mode, generation_mode, warnings`。四段 `segments` 固定为“场景判断/知识库依据/图文软文/核验结果”。HTTP 完成不等于核验 PASS，`report.overall=FAIL` 仍可作为正常结果包展示诊断。

统一错误体：`{error:{code,message,field_errors?,retryable},request_id}`。约定 400/422 参数或缺项、404 版本/资源不存在、409 版本过期或核验拦截、503 上游/服务不可用、504 超时。错误不返回原始密钥、完整上游响应或内部堆栈。

### 字段映射与必要增量

| 业务对象 | 当前差异 | 契约要求 |
|---|---|---|
| TaskSpec | 前端中文场景/渠道；后端固定英文 ID | 小红书→`xhs`，公众号→`wechat_mp`，朋友圈→`moments`，海报→`poster`；8 场景映射配置化；中文“开学季”→`school_season`；未知输入明确追问 |
| 缺项 | 前端缺字段标签；后端场景问句 | 返回 `{field,question}` 或字段到问句映射；明确必答与建议追问；显式已填写内容不能被重复追问循环阻断 |
| ContentPlan | 前端 `image_count/why`，后端 `image_min/max/length_min/max/avoid` | UI 展示区间和规则解释；不将范围伪造成固定数量；任务摘要来自返回的 TaskSpec |
| EvidenceMap | 本地 path、ima source、自带 `retrieval_mode` | facts 有 key/value/source，未知值允许 null 并标未确认；images 有 id/desc/source/matched_model/preview_url；型号依据来自实际选中产品而非原样复述输入 |
| DraftArticle | 前端 `pos`，后端 `position`，后端无 platform/product_hint | 统一布局字段为 `position`；稿件关联 task/version；适配器补展示标签；删除语义需要可编辑段落边界 |
| VerificationReport | 后端 `issues:string[]`、`unconfirmed:string[]`、`overall_pass` | 统一为 `overall:PASS|WARN|FAIL`、三项 `{pass,issues:[{level,text}]}`、`unconfirmed:[{field,reason}]`；空 issues 不代表执行过逐条核验 |

`PASS`：所有必须执行核验完成并通过，无待确认项。`WARN`：没有失败项，有未写成已确认承诺的待确认信息。`FAIL`：任一失败项、必要核验未执行、型号冲突、证据不足却输出参数。来源模式与核验结果分开显示；本地规则通过也不能显示为“ima 在线取证通过”。

## 7. 加载、错误与降级行为

- 所有请求立即反馈（目标 300ms 内），相关提交按钮禁用并标“处理中”；生成遮罩必须在成功和异常分支都能退出。减少动态效果设置不能改变真实业务进度。
- 建议状态/策略接口超时 35 秒、生成/修订整体超时 120 秒；各上游调用有独立超时。超时提示“未取得结果，可重试”，不能声称任务已停止；晚返回的旧请求不能覆盖新版本。架构可结合实际调用预算调整。
- 网络断开/后端未启动：说明服务不可达并给出本地启动入口；不自动切成前端 Mock。重新请求前保留输入。
- ima 失败：报告真实错误或脱敏原因；允许镜像演示时带模式标签降级，正式模式阻断。已配置凭证不能当作连通成功。用户确认的库与检索实际使用的库必须一致，不能每次默认取搜索第一项。
- 找不到产品/事实/图片：型号歧义先确认；无事实不生成带参数的终稿；图片不足显示实际数量及对应报告。图片解码失败保留说明、来源及重试入口，不影响页面其余信息可读。
- 返回改任务：已生成旧稿可以保留作历史，但当前任务编辑后不能继续沿用旧策略导出新稿。异步返回按任务/版本归属校验。
- 修订核验 FAIL：保留失败版本用于诊断并禁导出，可返回明确标识的上一通过版本；修订请求异常：保留原版本及输入，不假报修改已完成。
- 剪贴板不可用：提示改用 TXT/MD 下载；导出无后端连接时可使用已取得的当前版本规范化导出内容，必须保留原报告和模式，不能本地重新生成业务结果。

## 8. 验收标准

| 编号 | Given / When | Then |
|---|---|---|
| AC-01 | 服务启动后打开首页并重新探测 | 展示本次时间、实际库、掩码、真实模式；不存在预置“全通”；响应与静态资源没有密钥 |
| AC-02 | 任意删除 5 个必填之一，或直接向 API 提交空字段 | 页面追问且服务端拒绝出策略/稿件；已填字段保留 |
| AC-03 | 显式填写非默认人群、目标、阶段 | TaskSpec、策略摘要、四段输出和导出保持一致，不被默认值覆盖 |
| AC-04 | 同一产品分别选择四渠道；另将开学季换商务办公 | 渠道策略差异可见；场景切角和卖点改变；每渠道至少完成一条端到端生成路径 |
| AC-05 | 输入未知或有版本歧义型号 | 不返回随机最相近产品事实；给出可确认候选或阻断原因 |
| AC-06 | 有效结果打开成稿页 | 三栏、四 Tab、图片布局及核验属于同一版本；每张图和已使用参数可追溯；有真实图片则可预览 |
| AC-07 | 测试注入错误型号、证据外参数、无依据“999元”或“国补”，含 CTA 专项 | 后端产生明确失败项并拦截终稿导出；不能只靠前端隐藏按钮；无依据信息未输出时可以待确认提示 |
| AC-08 | 分别提交删最后段、换渠道、续航优先、屏幕优先、自定义 CTA | 逐项实际生效并重新核验；免责尾句保留；旧版本未被原地修改 |
| AC-09 | 将 CTA 改为“保证最低价999元”，点击重跑 | CTA 进入合规与事实检查；不得显示通过或允许终稿导出 |
| AC-10 | 正常生成后复制/导出 MD/TXT | 内容与当前预览一致，含模式、核验摘要和免责；MD 含配图与来源；TXT 可读；复制失败可下载 |
| AC-11 | 断网/关闭后端/制造上游超时、重复点击、快速换任务 | 无永久遮罩、重复覆盖或假成功；原输入可恢复；只接收当前有效请求结果 |
| AC-12 | 无 ima 凭证但本地镜像可用；再将两者均设不可用 | 前者明确显示镜像演示，后者阻断；不把内置 Mock 事实展示成真实取证 |
| AC-13 | 通过 Hash 直接访问未解锁页面或访问过期结果 | 导航门禁生效；结果缺失/版本过期有可行动提示，不出现空白或旧签章 |

验收证据至少包括：四渠道端到端结果、五种修订操作结果、一次真实错误与降级记录、一次 CTA 拦截、一次未知型号、同版 MD/TXT。外部凭证不可用时只能标记线上取证未验收，不能用镜像测试替代线上通过。

## 9. 待澄清与风险

1. **正式验收是否强制纯 ima 来源**：方案明确 ima 来源红线，现有 Python 允许本地镜像和 Mock。本 PRD 默认正式模式只接受 ima；本地镜像允许作为带明显标签的开发演示。需要主理人最终确认赛题验收口径。
2. **指定库名称**：前端“华为PC营销知识库”，后端默认“任德耀新建华为PC知识库”。以服务端配置和实际锁定 ID 为准，不应继续展示写死的演示库名。
3. **默认产品**：前端 `MateBook X Pro 2024`，后端示例主要覆盖 MateBook 14。必须先严格验证默认产品是否有独立版本事实，不能通过模糊匹配掩盖缺失。
4. **核验可信度**：当前事实检查默认通过，图像检查未实际比较型号，CTA 被遗漏；这些是 P0 质量风险。接上接口后若未修复仍不满足“有据、可核验”的交付目标。
5. **策略与可用证据不匹配**：卖点为长描述，事实 key 往往是短字段，当前模板可能匹配不到；公众号 1500–3000 字也可能因事实不足而无法达标。应明确证据不足诊断，不能注水补参数或调低门禁假通过。
6. **修订含义不一致**：后端现有“删减”只是调整长度，且可能修改原对象；P0 必须实现当前前端精确控件语义，否则需要明确改 UI 文案并由主理人确认。
7. **在线图片缺口**：当前 ima 分支未实际获取媒体，线上完整图文验收可能受阻；不能因本地预览成功声称线上图源流程完成。
8. **本地运行入口变更**：真实接入需要 Python 服务；双击 HTML 无法独自提供 API。应提供一个明确启动命令或启动入口，正式访问本地服务同源地址。

本文不要求重构七层架构，不要求新上模型厂商；若暂时保留模板生成，必须清楚展示实际生成模式并仍完成证据约束和核验。
