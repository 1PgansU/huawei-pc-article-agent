## 1. 设计原则（赛题红线）

| 红线 | 架构应对 |
|---|---|
| 自研系统不能只是 ima 转发 | Agent 必须含「场景理解 → 策略决策 → 核验拦截」三段独立逻辑，不调用大模型直接出软文 |
| 图片必须来自 ima、与型号一致 | 图片：ima 检索 → 型号校验 → 绑定事实点；不接外部图源 |
| 禁止虚构价格/补贴 | 事实核验白名单：无 ima 依据的字段一律「待确认」，不编造 |
| 平台必须真正差异化 | 平台策略为独立模块；结构/语气/配图数/引导由 ContentPlan 产出 |
| 凭证不能进源码 | ima 调用走环境变量网关；界面与代码中无完整 Client ID / API Key |

## 2. 后端七层架构（与前端对应）

```
用户交互层 (本方案 5 页 UI)
        │
1. 意图与任务理解层 → TaskSpec
2. 场景与平台策略层 → ContentPlan
3. ima 知识库检索层 → 原文 + 图片
4. 事实点提取层 → EvidenceMap
5. 图文编排与软文生成层 → DraftArticle
6. 核验与合规拦截层 → VerificationReport
7. 反馈与修改层 → 重跑 5→6 + 导出
```

**ima 边界**

| 能力 | ima | 自研 Agent |
|---|---|---|
| 产品事实 / 图片 / 知识库读写 | ✅ | ❌ 不二次构造、不接外图 |
| 场景识别 / 平台策略 / 编排 / 生成提示词 / 核验 | ❌ | ✅ |

## 3. 赛题功能板块 ↔ 页面映射

| 赛题功能板块 | 最低要求摘要 | 落在哪一页 |

| 修改与导出 | 临时修改后重生；复制/导出终稿 | **页5 修订页** |

## 4. 前端信息架构：5 页

### 全局顶栏（每页固定）

- 左：产品名「华为PC营销软文智能体」· 副标「自研编排 · ima取证」
- 中：5 步进度（连接 → 任务 → 策略 → 成稿 → 修订）；未完成不可乱跳；成稿通过后才解锁「修订」
- 右：账号掩码 · 知识库连接状态灯（绿/红）

---

### 页1 · 连接页（账号与知识库）

**目标**：评委进场第一眼确认「连的是指定库、密钥没泄露」。

| 区块 | 行为 |
|---|---|
| 账号身份卡 | 当前身份脱敏；Client ID 仅末 4 位 |
| 知识库锁定卡 | 库名、`kb_id`、连接状态、最近 API 探测时间 |
| 探测结果 | 关键 OpenAPI 是否通；失败给可行动错误文案 |
| 主按钮 | 「确认知识库，进入任务」（未连通禁用） |

**现场检查**：库名正确、状态绿、界面无完整密钥。

---

### 页2 · 任务页（任务输入）

**目标**：产出完整 `TaskSpec`；残缺任务必须追问。

| 区块 | 行为 |
|---|---|
| 表单 | `product_hint` / `audience` / `scenario` / `platform`（公众号·小红书·朋友圈·海报）/ `purchase_stage` / `user_question` / `content_goal` |
| 缺项追问条 | `missing_info` 非空时黄条列出缺项，补完才能提交 |
| 一句话预览 | 「为谁 · 什么场景 · 哪个平台」 |
| 主按钮 | 「生成内容策略」 |

**现场检查**：故意残缺任务 → 追问，不可直接出软文。

---

### 页3 · 策略页（场景与平台策略）

**目标**：可解释、可对比的 `ContentPlan`（评委改场景/平台时看差异）。

| 区块 | 行为 |
|---|---|
| 识别摘要 | 人群 / 场景 / 内容目标 / 平台标签 |
| ContentPlan 卡 | 切角、卖点排序、结构、语气、配图数、CTA |
| 差异说明 | 一句「为何该平台用此结构/语气」 |
| 操作 | 「返回改任务」 / 「按此策略生成图文」 |

**现场检查**：换场景或平台后策略明显不同且说得通。

---

### 页4 · 成稿页（检索 + 图文 + 核验）

**布局**：三栏 — 左取证 · 中稿件 · 右签章。

| 区域 | 对应模块 | 内容 |
|---|---|---|
| 左 · 取证栏 | 知识与图片检索 | 事实点列表；图片缩略+说明+ima 来源+匹配型号；可溯源 |
| 中 · 稿件栏 | 图文软文生成 | 标题/导语/正文/CTA/插图位；赛题四段 Tab：场景判断 / 知识库依据 / 图文软文 / 核验结果 |
| 右 · 签章栏 | 事实+合规 | 大号合规签章（通过/待确认/拦截）；逐条对 EvidenceMap；合规命中列表；价格无依据一律待确认 |

生成中展示七层流水线状态。拦截态不可进入修订，只能回策略或改任务。

**现场检查**：换机型抽查图源；混淆参数测事实核验；统一合规样例测规则。

---

### 页5 · 修订页（修改与导出）

| 区块 | 行为 |
|---|---|
| 修改指令 | 删段 / 换渠道 / 换卖点 / 改 CTA |
| 重跑说明 | 明确「将重跑图文生成 → 事实/合规核验」（层 5→6） |
| 对比（可选） | 改前/改后关键段落 |
| 导出 | 复制全文 · Markdown · 纯文本；可选附核验摘要脚注 |

**现场检查**：当场改渠道/卖点/删内容后能重生并通过核验再导出。

## 5. 视觉规范

### 气质

深色工业工作台 + 华为红强调；成稿预览用浅色「稿纸」对比。  
**合规签章**是唯一视觉主角。禁止紫渐变、Inter/Roboto/Arial 默认脸、Space Grotesk 套娃、满屏同圆角灰卡片。

### 色板（CSS 变量）

```css
:root {
  --bg: #0B0D10;
  --panel: #12151A;
  --panel-2: #1A1F27;
  --line: #2A313C;
  --text: #E8EAED;
  --muted: #8B93A1;
  --huawei-red: #C7000B;
  --huawei-red-soft: #FF2D3A;
  --pass: #1FA97A;
  --warn: #D4A017;
  --fail: #E5484D;
  --paper: #F4F1EC;
  --ink: #1A1A1A;
}
```

### 字体

| 用途 | 字体 |
|---|---|
| UI 标题 | Sora |
| UI 正文 / 表单 | Noto Sans SC |
| 软文预览 | Noto Serif SC |

字号阶：12 / 14 / 16 / 20 / 28 / 36。正文行宽约 40–68 汉字。

### 布局与组件

- 顶栏高 56px；内容最大宽约 1280px；成稿三栏约 `280 / 1fr / 320`
- 圆角：控件 8、卡片 12；签章可独立造型
- 主按钮实心华为红；次按钮描边；危险用拦截红描边
- 流水线四态：idle / running / done / blocked
- 动效：仅首入一页 stagger；尊重 `prefers-reduced-motion`

### 文案

短句、结论先行；CTA 说清结果；错误写清怎么修；密钥永远掩码。

## 6. 核心数据结构（前后端共用）

```jsonc
// TaskSpec
{
  "product_hint": "MateBook X Pro 2024",
  "audience": "大学新生",
  "scenario": "开学季",
  "platform": "小红书",
  "purchase_stage": "信息收集",
  "user_question": "兼顾学习、携带、续航",
  "content_goal": "种草+引导到店",
  "missing_info": []
}

// ContentPlan
{
  "angle": "轻薄+多设备协同+长续航，弱化跑分",
  "highlight_order": ["重量", "屏幕护眼", "续航", "生态"],
  "structure": ["口语化标题", "痛点开场", "3段场景", "行动引导"],
  "tone": "学姐分享风",
  "image_count": 4,
  "cta": "评论区扣1到店体验"
}

// EvidenceMap
{
  "facts": [
    {"key": "重量", "value": "1.26kg", "source": "kb#xxx/article#yyy", "title": "..."}
  ],
  "images": [
    {"id": "img_001", "desc": "机身侧视图", "source": "ima://...", "matched_model": "MateBook X Pro 2024"}
  ]
}

// DraftArticle
{
  "title": "...",
  "lead": "...",
  "body": "...",
  "cta": "...",
  "image_layout": [
    {"pos": "开头", "image_id": "img_001", "caption": "..."}
  ]
}

// VerificationReport
{
  "fact_check": {"pass": true, "issues": []},
  "image_check": {"pass": true, "issues": []},
  "compliance_check": {"pass": true, "issues": []},
  "unconfirmed": []
}
```

统一输出给评委时，严格四段式：**场景判断 / 知识库依据 / 图文软文 / 核验结果**。

## 10. 给同事的开工顺序

1. 读本文 §1–§4，对齐红线与 5 页  
2. 安装并启用 `frontend-design` skill（见同目录安装说明）  
3. 按 §5 建 CSS 变量与字体；先做顶栏 + 页1/页2  
4. 接 TaskSpec / ContentPlan API；页3 只读展示策略  
5. 页4 三栏接 EvidenceMap / DraftArticle / VerificationReport  
6. 页5 修改指令触发 5→6 重跑 + 导出  
7. 用赛题「现场检查」列做走查清单打勾
